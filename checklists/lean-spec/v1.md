# Lean spec checklist, v1

For the Lean module of a node whose `lean` names a model or a spec: the definitions that the page's procedure or definition becomes (11). Does the spec match the page?
Answer each question pass, fail or n/a; give a note for each fail. Yes means pass.

1. Does each Lean definition named in the node's `lean` define the object the page defines, with the same inputs and outputs?
2. Does the Lean procedure follow the steps of the page ("The method", "Definition") in the same order, up to the notation map?
3. Are the domains and types right: finite or general sets, reals or floats, natural or integer indices?
4. Are the edge cases handled as the page says (empty input, a zero denominator, ties)?
5. Is no hidden convention (truncated subtraction on naturals, division by zero, 0 log 0, a default argument) changing the meaning?
6. Are the notions taken from Mathlib or math2 the same as the page's, with the same conventions (log base, normalization)?
7. Do the small cases of AITest cover the page's worked example and its edge cases, not only easy ones?
8. Does each docstring describe its definition right, in the page's words?
9. Is every back-translation disagreement resolved or explained?
10. Does the page claim nothing about the Lean part that the module does not define or prove?
