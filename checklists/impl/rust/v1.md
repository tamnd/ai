# Implementation checklist: Rust, v1

For impl/rust/ of a node (X4). The build already runs the tests, the differential checks, lint and mutation; these questions need a person.
Answer each question pass, fail or n/a; give a note for each fail. Yes means pass.

1. Does the module docstring say what the code computes, and name the page and the equation ids right?
2. Does each block marked `eq: <id>` compute that equation of the page, in the page's form?
3. Can a reader read the reference side by side with the page: the same steps, and names from the notation register?
4. Is the reference the plainest code that matches the page, with any faster form moved to an `efficient` version?
5. Do the tests check the edge cases of the kind and the invariants the page states, not the code against itself?
6. Is each tolerance in the tests, and each loosening in contract.yaml or shapes.yaml, justified by a reason?
7. Is the code numerically careful where 08.11 asks (max subtraction, log-sum-exp, the page's eps, losses from logits)?
8. Does each shape comment give the right axes for its array?
9. Does versions.yaml say right how each labelled version differs, and list the differences of default of a `library` version?
10. Does the code use stable Rust and ndarray only, with no `unsafe`?
11. Does a bad shape give a clear error or panic message, never a silent wrong result?
12. Are axis orders of ndarray views right against the fixtures?
13. Is no code copied from the framework, a paper's repository or a tutorial?
