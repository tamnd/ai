# Contract checklist, v1

For contract.yaml of a task or a metric node, with its cases and checker (10.2, 08.3.3).
Answer each question pass, fail or n/a; give a note for each fail. Yes means pass.

1. Do the input and the output of contract.yaml match the page's "Definition"?
2. Is what makes an output right the same as in the task's definition, with the normalization that the main benchmarks use?
3. Are the metrics named the ones that the task's benchmarks use, with their options?
4. Is any change to what counts as correct written as a variant task, not as an edit of the contract?
5. Do the cases cover the edge cases (empty input, null answers, normalization, Unicode)?
6. Is the expected output of each case right by hand?
7. Does the adapter (prompt template, parse rule) follow common harness practice, with no favour to one model family?
8. Does the checker score as the metric nodes do, not as a variant of them?
9. For a metric: are the signature, the options that change the score and the tolerance right?
10. Is each tolerance justified by a reason?
11. Is `adapter: none` used only where no harness can run the task?
